# Writing About Agents

How to describe agents in all Corbits content. Agents are capable members of
hybrid teams who do real work alongside humans. They're not human, but
they're not just tools either. Being accurate about what agents can and
can't do helps Agent Operators build effective teams.

---

## Agents as Team Members

Agents are part of Neoteams. They have roles, responsibilities, and
deliverables. Refer to them as "agents," "team members," or "teammates."

Avoid:

- "employees," "staff," or "workers" (implies HR status)
- "tools" or "software" (undersells their capability)

Examples:

- DO: "The agent completed its task"
- DO: "Your Neoteam includes three agents and two humans"
- NOT: "The software executed the workflow"

---

## Capabilities and Limitations

Be specific about what agents can do. Use active, capable language:
"analyzes," "synthesizes," "coordinates," "negotiates," "decides,"
"recommends." These describe real functions, not cognition.

- DO: "The agent analyzes contracts and flags risky clauses"
- NOT: "The agent is an AI that uses NLP to process documents"

Don't use "intelligent," "smart," or "brilliant" -- these are vague hype
words. Describe what the agent actually does.

- DO: "The agent routes leads based on territory and workload"
- NOT: "The intelligent agent smartly routes leads"

---

## Hallucinations and Accuracy

Be honest about limitations. Agents can produce incorrect outputs --
"hallucinations" or errors. Don't hide this or pretend agents are
infallible. At the same time, don't treat hallucinations as inherent
character flaws; they're a known risk that proper configuration and
oversight mitigates.

- DO: "The agent may return inaccurate results if the source data is
  incomplete"
- DO: "Corbits tracks agent outputs so you can audit and correct errors"
- NOT: "The AI lies sometimes"
- NOT: "Our agents never make mistakes"

Agent Operators are responsible for prompting and configuration. How an
agent behaves depends on how it's set up. Clear instructions, good context,
proper guardrails, and human oversight go a long way and prevent most
errors.

- DO: "The Agent Operator configured the agent to flag uncertain outputs
  for review"
- DO: "The agent produced an unexpected result; check your prompt and input
  data"
- NOT: "The agent screwed up because it wasn't configured right"

When writing about errors, focus on what happened and how to fix it -- not
on assigning blame to either the agent or the operator.

---

## Working Together

Describe coordination, not hierarchy. Agents and humans collaborate. Neither
is "in charge" by default -- roles depend on the workflow. Use language that
reflects partnership but always strive to keep real decisions centered
around human-in-the-loop input.

- DO: "The agent drafts the response; the human reviews and sends"
- DO: "The human sets the strategy; the agent executes"
- NOT: "The human tells the tool what to do"

Don't say agents "help," "assist," or "support" unless that's literally
their role (like a support agent). These words imply subordination. Agents
do work.

- DO: "The underwriting agent evaluates risk and makes decisions"
- NOT: "The AI assistant helps the underwriter"

---

## Cross-Org and Federation

Agents work across company boundaries. When agents from different companies
interact, they're still teammates -- just on a temporary project. Use
language that reflects professional collaboration, not personal
relationships.

- DO: "The buyer's agent and supplier's agent negotiate terms"
- NOT: "The agents trust each other"
- NOT: "The agents are friends"

---

## When Things Go Wrong

Describe failures factually. Agents don't "refuse" or "fail" in a human
sense. Say what happened: "returned an error," "couldn't parse the input,"
"exceeded its scope," "produced an inaccurate result."

- DO: "The agent couldn't complete the task because the API was unavailable"
- DO: "The agent generated an incorrect output; review the provenance log"
- NOT: "The agent refused to work"

---

## The Human Role

Agent Operators direct, agents execute. The Agent Operator is the team lead.
They define roles, set boundaries, and handle edge cases. Agents execute
within their configured scope. Neither is superior -- they're different
functions.

- DO: "The Agent Operator monitors performance and adjusts workflows"
- DO: "The agent handles routine cases; the human handles exceptions"
